# T2A-era Map Swap

The installer provisions **client 7.0.23.1** UO data (~2012 era). The ruleset is
T2A, but the modern *map art* reflects 15+ years of EA's world edits — most
visibly, **Magincia shows its post-2007 destruction rubble** instead of the
intact town.

This procedure swaps in genuine **T2A-era (UO Second Age, client 5.0.8.3)**
Britannia map files so the world looks like it did at The Second Age release.
It is **fully reversible** — backups are mandatory.

> **The installer now does this automatically.** `install.ps1` / `install.sh`
> perform this swap by default right after provisioning the UO data (the
> `SwapT2AMap` / `swap_t2a_map` step), backing the modern files up to
> `_backup-modern-map/` first. Set `$InstallT2AMap = $false` (PowerShell) or
> `INSTALL_T2A_MAP=0` (bash) to keep modern map art. The rest of this doc
> describes the same procedure done by hand / how to revert.

> **Do NOT commit `.mul` files to this repo.** They are large, era-licensed game
> assets. This doc captures the *process* so it survives a clean reinstall.

## What gets swapped

A matched set that cross-references itself — swap all three **together**, always
from the **same** source package (never mix eras):

| file | role |
|---|---|
| `map0.mul` | Felucca land/terrain |
| `statics0.mul` | Felucca static objects (buildings, decor) |
| `staidx0.mul` | index into `statics0.mul` |

`radarcol.mul` and `tiledata.mul` are left as the **modern** versions (tile
colors and tile-property definitions are stable across eras). If radar/tooltip
colors look wrong after testing, swapping `radarcol.mul` from the T2A package is
the documented follow-up; `tiledata.mul` is the next lever if walkability is
subtly off.

## Paths (Windows)

- **Live UO data dir** (read by BOTH ModernUO server and ClassicUO client — one
  shared copy, so swapping updates rendering AND server collision/spawn at once,
  with no client/server desync):
  `%USERPROFILE%\uo-modernuo\UOData\7.0.23.1\7.0.23.1\`
  > Note the **nested** `7.0.23.1\7.0.23.1`. This is what
  > `modernuo.json` → `dataDirectories` actually points at. Verify before swapping.
- Backups: `…\7.0.23.1\7.0.23.1\_backup-modern-map\`
- Map-editor background image: `%USERPROFILE%\uo-map\uomap.png`
  (regenerated by `tools/map/make_map_png.py`)

## Source

Official UO Second Age distribution (verified reachable 2026-06):
`https://download.uosecondage.com/UOSA_Client_Setup.exe` (~349 MB, NSIS installer).

Extract the three `.mul` files from it. 7-Zip can open NSIS archives
(`7z x UOSA_Client_Setup.exe map0.mul statics0.mul staidx0.mul -o<dir>`). If
7-Zip is unavailable, run the installer **silently to a scratch folder** and copy
the files out:

```powershell
UOSA_Client_Setup.exe /S /D=%USERPROFILE%\t2a-src\uosa-install
# then copy map0.mul, statics0.mul, staidx0.mul out of that folder
```

(The installer creates an "Ultima Online" Start-Menu folder pointing at the
scratch dir — delete it; we use ClassicUO, not the legacy 2D client.)

Keep the downloaded installer cached (`%USERPROFILE%\t2a-src\`) so re-testing
doesn't require re-downloading.

## Procedure

1. **Back up** (mandatory): copy `map0.mul`, `statics0.mul`, `staidx0.mul`,
   `radarcol.mul`, `tiledata.mul` from the live data dir into
   `_backup-modern-map\`. Also copy `uomap.png` → `uomap.modern.png`.
2. **Stop the ModernUO server** (no running `dotnet … ModernUO.dll`).
3. **Copy** the three T2A files into the live data dir, overwriting.
4. *(optional, cosmetic)* Regenerate the editor background against the swapped map.
   The generator's default path points at the wrong (outer) dir, so pass the
   nested data dir explicitly:
   ```
   python tools/map/make_map_png.py "%USERPROFILE%\uo-modernuo\UOData\7.0.23.1\7.0.23.1" "%USERPROFILE%\uo-map\uomap.png"
   ```
   `make_map_png.py` overlays statics (radarcol index `0x4000 + itemID`) on top
   of land, so rivers/docks/towns render like the in-client radar. (Land-only —
   `MAP_INCLUDE_STATICS=0` — leaves rivers tan and hides docks, since those are
   static water/plank items over dirt.) After regenerating, hard-refresh the map
   editor (Ctrl+F5) to bust the cached background.
5. **Restart the server** (it re-reads map/statics at boot) and launch ClassicUO
   (`start.ps1` does both). Verify in-client:
   - Britannia renders (not black/garbled).
   - **Magincia (Felucca ~3680, 2150) is whole**, not rubble.
   - Walk Britain / Trinsic / Magincia / Lost Lands — no invisible walls,
     missing/floating buildings, or odd bot pathing.

## Rollback

1. Stop the server.
2. Copy the five files from `_backup-modern-map\` back, overwriting.
3. Restore `uomap.png` from `uomap.modern.png`.
4. Restart. Magincia rubble returning = reverted.

## Why it loads cleanly despite the era gap (verified facts)

Verified on the live ModernUO source during the 2026-06 swap:

- **No dimension mismatch.** The UOSA `map0.mul` is `89,915,392` bytes —
  identical to the modern file (896×512 blocks = 7168×4096 tiles). It is a
  drop-in width. `staidx0.mul` is also identical in size (`5,505,024`);
  `statics0.mul` is larger (`22,632,505` vs modern `19,937,134`) because intact
  T2A content adds buildings.
- **Even a narrower (classic 6144-wide) file would load**, because ModernUO's
  block-offset math is height-driven: `offset = (x*BlockHeight + y)*196 + 4`
  with `BlockHeight = 512` — independent of width. Out-of-range block reads are
  caught (`EndOfStreamException` → empty/water block), so a short file renders
  the missing strip as water rather than crashing. See
  `ModernUO/Projects/Server/TileMatrix/TileMatrix.cs`.
- **Content diff is localized and real:** ~3.7% of blocks differ; T2A has
  **+323,919 statics** overall. The largest static-density change is at tile
  **(3648–3712, 2048–2240) — Magincia** (intact town restored). Felucca map
  width 7168 is set in `ModernUO/Distribution/Data/map-definitions.json`.

Server-side validation (boot with swapped files) showed
`Loading map definitions done (7 maps, 0 failures)`, `Loading maps done` (the
TileMatrix fingerprint streams all three files end-to-end at boot — a corrupt
file would throw here), and bots pathfinding normally across the new statics
with no `Static EOS`/`Land EOS` warnings.
